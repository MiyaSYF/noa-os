006_ローカルの 4B モデルが実際のゲームをプレイし、ゲームがその選択を受理しました

2026年9月20日、ローカルで動かしている Qwen3.5-4B（LoRA アダプタ付き）が、Luck be a Landlord v1.2.24 の実際の状態を読み取り、有効な選択肢の中から一つを選び、ゲームがそれを受け付けました。ゲームは Steam 版を隔離して複製したもので、小さなブリッジを注入しています。モックでも、ハードコードされたルールでも、座標クリックでもありません。ポップアップのボタンを誰かが代わりに押したわけでもありません。

choice          : shiny_pebble
speech          : キラキラ石でいいや。
mood            : happy
source          : model
model latency   : 5.428 s
fallback_reason : null
decide accepted : true

経路の全体は次のとおりです。

LBAL v1.2.24 (isolated copy) + injected bridge
→ local TCP, UTF-8, one JSON object per line
→ Python orchestrator
→ local HTTP model service (WSL, GPU)
→ decision_id / choice / speech / mood
→ orchestrator re-validation
→ bridge resolve_event(choice)
→ game accepts the choice and returns to idle

最初にうまくいかなかったこと

1. 画面座標をインターフェースにしたこと。クリックでボタンは押せますが、状態は何も得られません。候補の選択肢、イベント ID、盤面はピクセルから復元できず、ウィンドウ位置、解像度、アニメーションのタイミングですぐに破綻しました。主経路としては破棄しています。

2. 復元プロジェクトと汎用 Mod Loader。復元した Godot 3.4.4 のプロジェクトは、エディタでは一度も動きませんでした。これは早い段階から分かっており、最初の判断、つまり「深追いせず、読み取り専用の資料として残す」は正しいものでした。間違いはその後です。再び復元を試み、さらに Godot 3.5 向けの Mod Loader（v6.3.0）を 3.4.4 のカスタムビルドへダウングレードして載せようとしました。一つ直すと、次のエラーが現れました。

Time singleton missing
ProjectSettings global class info missing
PoolStringArray API mismatch
class_name / dependent scripts not registering

本当の要件は、ローカルポートを一つ開き、ゲーム内の関数を二つ呼ぶことだけでした。そこで、すでに動作が証明されていた部分（override.cfg による注入と、PCK に含まれない単体スクリプトの読み込み）だけを残し、Godot 3.4.4 標準の API だけを使う最小限のブリッジを書き、WebSocket をエンジン標準の生の TCP に差し替えました。

関門ごとに証拠を取る

ステージ示したこと
S1 注入元のランタイム上でブリッジが存在し、元の PCK の SHA-256 は変わっていませんでした。
S2 ハンドシェイクhello、ping/pong、heartbeat が通りました。メニューにいる間、SceneTree.paused は false でした。以前の推測はここで訂正されました。
S3 読み取り専用の状態idle → busy → event_pending、coins 1 → 0 → 5、rent [25, 5] → [25, 4]。
S4A / S4A5 初めての書き込み書き込みは spin のみ。選択肢は実行時にポップアップから読み取ります（popup.emails[0].type、popup.cards[].data.type、popup.buttons[].args[0]）。モデルは推測ではなく、許可リストの中から選びます。
S4B 安全な Decidedecision_id は使い捨てのトークンです。拒否ゲート五つがすべて作動しました：選択肢にない choice、期限切れの ID、重複リクエスト、解決済み、UI 未準備。正しい選択はちょうど一度だけ実行されました。
S4C イベントの網羅175 件の状態、155 件の有効な decision、12 種類のイベント。一時的な読み取りエラー 20 件（ポップアップのアニメーション中で、UI コントロールがまだ有効でない時点）は、すべて次のサンプリングで解消しました。
S4D 再接続実際の WinError 10053 による切断、再接続、新しいランをまたいだノードの再バインド。長時間の耐久試験ではありません。
S4E 決定論的ループLLM なしのルールベースです。75.3 秒、44 回のスピン、67/67 の decision を受理、6 回の家賃支払い、最終 coins/rent は 257/375、終端は game_over、再接続 0 回、プロトコルエラー 0 件でした。

S4E では spin_cooldown による拒否も 149 回記録されました。安全ゲートは正しく動作しており、クライアント側のリトライの間隔が短すぎただけです。そこで V2 の Orchestrator に 1.25 秒のバックオフを入れました。

証明する必要があったデータの意味

  • floor は選択した難易度であり、ラン内の進行度ではありません。landlord_hp は 750、1000、1500 のいずれも正当な値です。
  • queued_increase = -1 は coins に合流する前の符号付きの増分で、ここではスピンのコストを表します。エラーを示す番兵値ではありません。
  • 過去の長いランでは coins が数十億に達したので、データ経路のどこにも 32 ビット整数は使えません。Godot 3 の JSON.parse は入力された数値を double として読むため、2^53 − 1 を超えると整数の精度が失われます。現在のブリッジは JSON を出力するだけで、読むのは Python 側です。精度の劣化は観測されていません。将来、大きな整数をブリッジへ送るなら、10進の文字列にする必要があります。この点は未解決です。
  • effects / items / destroyed の履歴全体を、そのままプロンプトに入れることはできません。

基盤側のつまずき

ランチャー。Windows のパスを wslpath に渡すと、バックスラッシュが消えました（C:\dir\sub が C:dirsub になります）。戻り値は空で、null に対する .Trim() が落ちました。その修正版は PowerShell の中で C 風の引用符エスケープを使い、ParserError になりました。三度目のパッチを重ねる代わりに、Stage 3 V2 を作り直しました。メインのランチャーは CMD、wslpath は不使用、タイムアウトを明示し、デフォルトのフォールバック、出力の検証、スピンのバックオフを備えています。

ネットワーク。モデルの読み込みは、Hugging Face へのリクエストで 120 秒も止まりました。GPU に問題はありませんでした（RTX 5070、CUDA、BF16、Xformers をすべて認識）。本当の原因は、WSL の NAT モードが Windows 側の localhost プロキシを認識していながら、利用できなかったことです。オフライン用の応急修正は用意済みでしたが、先に長期的な対処を選びました。ミラードネットワークを有効にし、autoProxy、dnsTunneling、firewall をオンにしました。するとプロキシの警告は消え、重み 723/723 が 5 秒で読み込まれました。

最初の実際の判断

モデルサービスに対する最初の契約テストは、choice: gambler、mood は excited、警告なしでしたが、所要時間は 20.469 秒でした。Orchestrator の 20 秒のタイムアウトをわずかに超えたため、実機での検証では 45 秒に引き上げました。ウォームアップ後の判断は 5.428 秒でした。

実際のイベントは add_tile で、選択肢は shiny_pebble、goose、bee、skip（既定は skip）、coins 5、spins 1、家賃 25 を残り 4 スピンで支払う状況でした。モデルは shiny_pebble を返しました。Orchestrator は、decision_id が一致していること、choice が選択肢に含まれること、speech が空でないこと、mood が許可リストにあること、タイムアウトもフォールバックもないことを確認しました。その後ブリッジは accepted = true を返し、状態は event_pending から idle へ戻りました。

ステージ 1 から 3 は合格です。声と立ち絵は、まだ接続していません。

検証範囲と制約：この回のモデル主導の部分は受理された判断 1 回のみです。67 回の decision はルールベースの実行でした。盤面上の対象選択、Symbol の固有 ID、右クリック無効の状態は、まだプロトコルに入っていません。長時間のメモリ耐久試験もありません。TTS の音声、リップシンク、mood からアバターへの接続も未実装です。モデル主導で 1 ラン通したときのコスト、レイテンシ、フォールバック率は未計測です。

受理された一行を聞くまでに、関門は九つありました。
