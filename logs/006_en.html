006_A local 4B model played a real game, and the game accepted the move

On 2026-09-20 a locally hosted Qwen3.5-4B (with a LoRA adapter) read live state from Luck be a Landlord v1.2.24, chose one of the legal options, and the game accepted it. The game was an isolated copy of the Steam build with a small bridge injected. There was no mock, no hardcoded rule, no coordinate clicking, and nobody pressing a button on the popup.

choice          : shiny_pebble
speech          : キラキラ石でいいや。   (roughly: "A shiny rock will do.")
mood            : happy
source          : model
model latency   : 5.428 s
fallback_reason : null
decide accepted : true

The full chain:

LBAL v1.2.24 (isolated copy) + injected bridge
→ local TCP, UTF-8, one JSON object per line
→ Python orchestrator
→ local HTTP model service (WSL, GPU)
→ decision_id / choice / speech / mood
→ orchestrator re-validation
→ bridge resolve_event(choice)
→ game accepts the choice and returns to idle

What failed first

1. Screen coordinates as an interface. Clicking could press buttons but carried no state. Candidate options, event IDs and the board were not recoverable from pixels, and window position, resolution and animation timing broke it. Abandoned as the main path.

2. The decompiled project and a generic mod loader. The decompiled Godot 3.4.4 project never ran in the editor. That was known early, and the first decision, to stop chasing it and keep it as read-only evidence, was correct. The mistake came later: re-decompiling, then downgrading a mod loader (v6.3.0, built for Godot 3.5) onto a 3.4.4 custom build. Each fix exposed the next error:

Time singleton missing
ProjectSettings global class info missing
PoolStringArray API mismatch
class_name / dependent scripts not registering

The actual requirement was to open a local port and call two in-game functions. The fix was to keep what had already been proven (the override.cfg injection and loose-script loading), write a minimal bridge that uses only native 3.4.4 APIs, and replace WebSocket with the engine's raw TCP.

S4E also logged 149 spin_cooldown rejections. The safety gate was correct and the client was retrying too aggressively, so the V2 orchestrator got a 1.25 s backoff.

Data semantics that had to be proven

  • floor is the chosen difficulty, not in-run progress. landlord_hp of 750, 1000 and 1500 are all legitimate.
  • queued_increase = -1 is a signed delta waiting to merge into coins (here, the spin cost), not an error sentinel.
  • Coins reached billions in historical long runs, so nothing on the path can be 32-bit. Godot 3's JSON.parse reads inbound numbers as doubles, which loses integer precision above 2^53 − 1. The bridge currently only emits JSON and Python parses it, and no precision loss has been observed. If large integers are ever sent inward, they must be decimal strings. Unresolved.
  • The full effects/items/destroyed history cannot go into the prompt as is.

Infrastructure failures

Launcher. A Windows path passed through wslpath lost its backslashes (C:\dir\sub became C:dirsub), nothing was returned, and .Trim() on null crashed. The follow-up fix used C-style quote escaping inside PowerShell and hit a ParserError. Stage 3 V2 was rewritten instead of patched a third time: CMD as the main launcher, no wslpath, explicit timeout, default fallback, output validation, spin backoff.

Network. Model loading hung for 120 s on a Hugging Face request. The GPU was fine (RTX 5070, CUDA, BF16 and Xformers all detected). The real cause was WSL's NAT mode seeing the Windows localhost proxy but being unable to use it. An offline hotfix was ready, but the long-term fix went in first: mirrored networking with autoProxy, dnsTunneling and firewall enabled. Afterwards the proxy warning was gone and 723/723 weights loaded in 5 s.

The first real decision

The first contract test against the model service returned choice: gambler, mood excited, with no warnings, but took 20.469 s. That just exceeded the orchestrator's 20 s timeout, so it was raised to 45 s for acceptance. Once warm, the decision took 5.428 s.

The live event was add_tile with options shiny_pebble, goose, bee, skip (default skip), 5 coins, 1 spin, and rent 25 due in 4 spins. The model returned shiny_pebble. The orchestrator confirmed that the decision_id matched, the choice was in the options, the speech was non-empty, the mood was in the allowlist, and there was no timeout and no fallback. The bridge then reported accepted = true and the state moved from event_pending to idle.

Stages 1 to 3 pass. Voice and avatar are not connected yet.

Boundary: the model-driven part of this run is one accepted decision; the 67-decision run was rule-based. Board-target selection, unique symbol IDs and right-click-disabled state are not in the protocol yet. There has been no long-run memory soak. TTS audio, lip sync and mood-to-avatar are not wired in. Cost, latency and fallback rate over a full model-driven run are unmeasured.

One accepted line took nine gates to hear.
