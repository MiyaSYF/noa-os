008_When a Diamond Isn't a Diamond

The decision model repeatedly favored two symbols for the wrong reasons: it confused a coin symbol with player currency, and interpreted a playing-card suit as a gemstone.

Both issues were addressed by making the model-facing descriptions more explicit. The fixes worked in subsequent observations, although no reliable before-and-after counts were retained.

What happened

1. Coin: symbol vs. currency

The game has two distinct concepts:

  • Coin symbol: a board symbol with a low base value and no intrinsic special effect.
  • Player currency: the numerical resource used to pay rent.

Both were described using the same term, making the distinction unclear in the model's input.

The initial descriptions also failed to communicate that an absent effect description meant the symbol had no intrinsic special effect. Instead, the wording could be interpreted as missing information.

The rule catalog was revised to distinguish the symbol from the currency and explicitly describe its default behavior.

One detail mattered: the coin symbol belongs to a group referenced by other game mechanics. Having no intrinsic effect does not mean having no possible synergy. The revised description preserved that distinction.

2. Diamonds: context interference and missing semantics

The model also showed an unexpected preference for diamonds, a playing-card suit represented by a red diamond-shaped symbol.

The game contains two separate concepts:

IdentifierMeaning
diamondsPlaying-card suit
diamondGemstone

The original model-facing description only identified the first as 「ダイヤ」, without explicitly stating that it was a playing-card suit.

There was another possible source of confusion. Noa's persona description used an idiom involving sparkling eyes when talking about favorite things. The model repeatedly produced remarks about shiny objects, raising the possibility that this character context influenced its evaluation of the diamond symbol.

The debugging process involved two stages:

  1. The persona wording was revised to avoid the literal association with sparkling objects.
  2. The four playing-card suits were explicitly labeled as card symbols. When this was insufficient, the description was made more concrete: ダイヤ（♢、ひし形）.

The final model-facing terminology also separated Suit_Diamonds from Gem_Diamond.

Changes and observations

  • Coin symbol and player currency were explicitly distinguished.
  • Symbols without intrinsic effects were described as such, without incorrectly ruling out external synergies.
  • Playing-card suits were identified by both category and visual shape.
  • Persona wording and symbol descriptions were revised.
  • Both unwanted selection tendencies stopped appearing in subsequent observations.

Engineering takeaway

Natural-language labels are not neutral identifiers. A familiar word can activate associations from unrelated parts of the context, while an omitted attribute can leave the model to infer semantics that the game never intended.

Model-facing data does not need to use the same vocabulary as user-facing text. Explicit identifiers and concrete attributes can be more useful than elegant descriptions.

Boundary: The observations came from actual game runs, not a controlled ablation study. Persona wording and game-symbol descriptions were changed during the debugging process, so their individual contributions cannot be isolated. No reliable before-and-after selection counts were retained. The proposed influence of the persona wording on diamond interpretation remains a hypothesis, not a confirmed causal explanation.

A symbol's name is not its specification.
