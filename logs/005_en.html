005_Style Crushed Capability (Provisional)

v5 training finished cleanly in twelve minutes, with a loss that had nothing to complain about. Then the model fell apart in evaluation. This entry covers two cases: one closed, with an invisible character as the culprit; and one still open, with the learning rate and our own dataset under investigation.

Training Was Not the Problem

  • 275 three-language samples: 298 database rows exported, with 23 excluded for visual dependence, lyric dependence, proactive prompts, or memory samples containing question-setting instructions.
  • A new LoRA was trained from scratch: r=32, alpha=64, dropout 0.05, 4 epochs, learning rate 2e-4. The v4 adapter was not continued.
  • 140 steps, roughly 12 minutes, train_loss 1.253. Training itself was never the bottleneck.

Closed: Ghost Character U+DCE3

Some inputs made the tokenizer crash immediately:

TypeError: TextEncodeInput must be Union[TextInputSequence, Tuple[InputSequence, InputSequence]]

Pasting Japanese text worked. Pasting it, deleting one character, and typing it again caused a crash. The log showed an invalid surrogate character, U+DCE3, hidden inside the user message. It looked like clean Japanese on screen, but the underlying bytes were:

ノアは遊ぶゲ\udce3は遊びたいゲーム

The terminal editor had damaged a multibyte UTF-8 sequence, and Python preserved the invalid byte through surrogateescape. Strictly encoding the completed prompt template reproduced UnicodeEncodeError without loading the model. It was not a spacing problem, an authorization problem, or overfitting.

The fix is deliberately boring: enable readline at the chat entry point, validate Unicode before writing input to history or the prompt template, and reject invalid input explicitly. Do not silently delete or replace characters.

Before blaming the model, verify that the bytes actually contain the sentence you thought you sent.

Open: Evaluation Still Fails

  • Identity drift: asked for its name, the model answered “Nao”; phrased another way, it launched into a long explanation using “I” as if that were the answer.
  • Unreliable factual recall: asked for a real horror game, it invented “Psycho Brief,” a title that does not appear to exist.
  • Weak task tracking: a game-selection conversation drifted into a movie about AI ruling humanity, then ended with the model admitting that it had no title.
  • Poor transfer to ordinary topics: laundry, which was not represented in the training set, produced awkward conversational handoffs.

The comparison used the same v5 prompt, greedy decoding, and the same eight test groups / twelve responses.

Working Hypotheses

  • Style and capability may be trading off: the more strongly a version expresses Noa’s character, the worse its factual and task performance appears. This is not a verdict on a single cause.
  • With the same data and seed, an earlier checkpoint at the lower learning rate handled knowledge questions better. That supports keeping early checkpoints, but does not prove that 2e-4 is always too high.
  • The dataset already distinguishes wanting a body from wanting to become human. The model still answered, “I want to become human.” Writing a subtle boundary into one example does not guarantee that the model will respect it.

The Evaluation Set Confesses

The fixed eight test groups overlapped with training samples. Exact reproduction proves neither overfitting nor generalization. Reusing the same questions to choose checkpoints may have baked selection bias into the “best” checkpoint. The next round must include questions unfamiliar to both the model and the person writing them.

Takeaway

  • When something crashes, inspect the input before inspecting the model.
  • Do not use checkpoint-selection questions as the final evaluation.
  • Training takes twelve minutes; understanding what was trained takes all night.
  • Negative results still count as assets. v5 leaves us one candidate checkpoint and a much sharper list of questions.

Boundary: checkpoint 70 is only a provisional baseline, not a passing model. “Overfitting” remains a hypothesis, not a conviction. The U+DCE3 diagnosis is strongly supported, but has not yet been reproduced byte-for-byte in a complete experiment. Do not infer that every unnatural answer came from the bad character. The sample size is still small, and the eight test groups are not an independent validation set.

The model never answers the sentence you see on screen. It answers the sentence that exists in the bytes.
