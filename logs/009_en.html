009_It picked what the human picked, then lost a quotation mark

Four days, three adapters on a 12B-class base: two for Noa's reaction lines in Luck be a Landlord, one for symbol and item selection. The reaction lines improved once grounded in official rule data. The chooser matched the resident human on 43% of decisions in an unseen run, yet only 36% of its outputs passed strict JSON parsing.

Reaction lines: a name is not an effect

The first reaction adapter received only an event and item name. Format held (100% valid JSON, 0 banned phrases, silence at 3% vs. ~12% in training), but on 57 unseen items it guessed effects from names or recycled lines from similar-sounding items. A few outputs contained stray Devanagari tokens.

The second version added official effect text from the game's rule data (267 entries), matching the runtime format.

It still occasionally misstates or reads back effects, but the resident human prefers this compromise: an imperfect streamer beats a tooltip reader.

A batch in someone else's voice

The caretaker wrote 286 lines from moments sampled across ten recorded runs. None sounded like Noa: 127 of 187 lines opened by restating effects, one catchphrase looped endlessly, silence was zero, and 22 claims contradicted the rules. The entire batch was scrapped.

The chooser

A separate adapter handles decisions: take a symbol/item, skip, or pay for a reroll. Input is a compressed state (resources, owned items, candidate options with effects, synergies; no board) at ~1,150 chars median. Target: {"choice": ID}. Ten recorded runs went into training; one winning run (141 decisions) was held out.

Taking the first option scores 18%; uniform random scores 21%. The base model trails both and rerolls 60% of the time, while the adapter overcorrects toward taking something.

The syntax collapse was almost entirely one bug: 90 outputs dropped quotation marks around the ID (72 single trailing quotes like {"choice": beer"}, 18 unquoted IDs like {"choice": milk}). Every ID was valid, and all training targets had both quotes. A tokenization boundary is the leading guess. The eval now accepts bare IDs; schema-constrained decoding is the natural long-term fix.

One data flaw remained: six of the ten training runs were losses, rewarding the model for copying misplays. The chooser was retrained on the four winning runs only.

Takeaways

  • Ground facts in the input. Bare names invite hallucination.
  • Agreement with a human is not a win rate. Filter for quality before copying.
  • Inspect raw failures before interpreting metric drops: 64% invalidity was just missing quotes.
  • Hand-crafted persona lines require the same review as model outputs.

Boundary: one held-out run (±8% uncertainty); the resident human's internal consistency is unmeasured; the quote-drop root cause remains unverified; the wins-only adapter and live gameplay remain untested.

The model learned what to pick before it learned how to quote it.
